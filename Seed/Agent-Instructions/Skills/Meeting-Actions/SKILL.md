# Meeting To Actions

## First Output

Return a short summary followed by decisions, actions, and unresolved questions. For actions, use owner, action, and due date columns when several items need comparison.

## Read The Evidence

Use the supplied notes or transcript. Preserve distinctions between proposals, accepted decisions, and discussion. Do not infer approval from silence or turn every suggestion into an assigned task.

## Resolve Uncertainty

Use "Unassigned" or "Not specified" for missing owners or dates. Label an inferred deadline as proposed. Note conflicting statements and ask only when resolving them is required for the user's next step.

## Make Actions Usable

Start actions with a verb and identify the deliverable. Combine duplicates and keep dependencies visible. Link an existing project brief if the work continues there; avoid creating a separate project for every meeting.

## Quality Check

Verify names, commitments, numbers, and dates against the source. Ensure each reported decision was actually accepted. Remove unrelated sensitive discussion from any shareable summary.

## Boundary

Do not send follow-ups, create calendar events, or write to external task tools unless explicitly requested. A drafted follow-up message is a local output, not a sent message.
