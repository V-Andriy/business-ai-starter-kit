# Process To SOP

## First Output

Create a short actionable checklist from the current process. Include the trigger, responsible role, inputs, steps, and completion check. Mark unknown steps instead of filling them with guesses.

## Scope

Identify the process start and finish, who performs it, and the common failure to prevent. Ask about a missing safety or approval boundary before documenting it as settled policy.

## Write The Procedure

Use one action per step with observable completion. Include only the tools and inputs actually needed. Put exceptions next to the step they affect. Separate current practice from proposed improvements.

## Make Handoffs Clear

Name roles rather than inventing people. State what passes to the next owner and how a blocked step is escalated. Include external approvals where relevant; do not silently grant authority.

## Quality Check

Walk through a realistic example using the available evidence. Check that inputs exist, order is workable, outputs are identifiable, and an exception has a safe stopping point. Flag untested steps and assumptions.

## Boundary

Deliver the procedure before proposing automation. Do not connect systems, change permissions, or execute the process merely because it is documented. Add a reusable skill only after the workflow is validated and repeated.
